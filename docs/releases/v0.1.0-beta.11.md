# FCS-Scribe v0.1.0-beta.11

Experimental beta addressing **S08: exports overwriting inactive tracking
projects**.

## Changes since v0.1.0-beta.10

- Protect recognized active/inactive tracking anchors, copied tracking JSON,
  backups and reserved `.json.scribe` storage. Workshop export needs no open
  project for protection. Empty/interrupted storage still reserves its anchor.
- Explain the rejection and require a separate filename. Following the selected
  policy, refuse unreadable or malformed existing JSON rather than relying on
  a generic overwrite confirmation.
- Keep valid existing AI packets (including schema-3 ranges), Workshop exports
  and ordinary JSON objects replaceable. Keep formatted UTF-8 output.
- Stage and flush AI/Workshop exports, recheck destination classification and
  original hash, then atomically create/replace without touching neighboring
  `.bak` files. Pre-commit failures preserve the previous destination.
- Protect draft workspace destinations and their backup-rotation targets;
  retain stricter workspace-only replacement and save/discard behavior.
- Prevent new preview archives inside reserved tracking folders while retaining
  new-file-only, original-byte and outside-Kenshi restrictions.
- Update the README, wiki and stabilization plan. No tracking, journal, packet,
  workspace or settings schema migration. S09-S16 remain open.

## Installation and compatibility

Requirements: Windows, .NET Framework 4.8, installed FCS Extended and the
inspected Steam FCS 2.14.2 executable with SHA-256:

```text
3688c4d8421d51c2d30c2ff0338874779d91eff150c6a02bf415bc1cdd9c7796
```

Close FCS, extract the archive and copy its `FCS-Scribe` folder into
`<Kenshi>\mods\FCS-Scribe`, replacing older plugin files when upgrading.
Launch FCS Extended and enable FCS-Scribe. Back up your mod projects and FCS
notes files first. Building/downloading does not install or change your game.
Existing projects need no migration; keep baseline and `.scribe` folder together.

## Protection boundaries

Recognition is independent of project health, but not every arbitrary file can
be identified as tracking history. A standalone old AI packet without tracking
identity or adjacent storage is still an export. Preserve damaged files and use
a new destination. These are local consistency checks, not authentication, a
universal filesystem-alias/race lock or a power-loss guarantee.

Tracking is not a mod backup; exports never save mods or apply notes.
Full interactive FCS Extended acceptance (S09), large-model/history performance
(S12) and broader storage/backup/privacy safety (S13) remain open.

## Validation and source

Recorded checks: **593 core**, **266 existing vanilla plus 16 settings,
24 scheduling and 24 export protection**, and **265 existing representative-mod
plus 16 settings, 24 scheduling and 24 export protection** passed. The
representative mod has no instances; that mutation remains covered by vanilla.

Core cases include recognized/copied anchors, markers/backups, orphaned
storage, malformed/unreadable destinations, escaped/duplicate format fields,
multiple JSON roots, BOM-marked UTF-8/UTF-16, valid existing schema-2/3 exports,
pre-commit write/flush/commit faults and concurrent conversion/reservation.
Actual window helpers verify Workshop with no project open, AI/workspace write
paths, backup rotation, valid existing exports and new-preview storage guards.
Rejected project files retain every original hash. Fresh isolated 32-bit hosts
exercise disposable copies, not the live installation. Native file dialogs,
complete FCS Extended startup, exhaustive ACL/network/power-loss behavior and
physical filesystem alias enumeration remain unverified.

The ZIP contains the plugin, manifest, README, documentation, GPL-3.0 license
and `release.json` identifying the exact source commit. No Kenshi, FCS or
upstream FCS Extended binaries are bundled. Verify the ZIP against its
`.sha256` asset; the matching Git tag/source archives supply corresponding source.

# FCS-Scribe v0.1.0-beta.14

Experimental beta publishing **partial S12 performance progress**. The user
selected publishing bounded history/profiling improvements while keeping
full-capture memory work and a sustained real-editor soak open. **S12 is not
closed**, and S13/new feature expansion is not automatically started.

## Changes since v0.1.0-beta.13

- Hash-check every observed session and the journal during compilation,
  but skip redundant JSON/packet parsing of already validated, fully compiled
  sessions. New recordings invalidate their session's completed status.
- Validate each session line once rather than twice during Resume. Remove
  one duplicate session hash pass for changed recording; unchanged reviews
  still verify the session, and append retains its prewrite/full-file checks.
- Add reproducible x86 synthetic history profiles and optional copied-native
  data profiling, with machine-readable latency/memory/workload reports.
- Document measured envelopes, large-stack UI pauses, private fixture handling
  and unresolved 32-bit memory limits. No automatic archival/pruning or forced
  GC is added.

No schema, fingerprint, evidence identity, durable flush, replay-chain,
snapshot-validation or original-retention contract changes.

## Measurements and remaining boundary

On the paired 2,000-record / 100-entry / 10-session synthetic profile,
median no-op compilation fell from **2,417.7 ms to 40.3 ms** (about 60x).
Pending compilation fell from 1,421.4 ms to 257.0 ms. Larger profiles cover
300 entries/30 retained sessions and a 20,000-cell changed record, with explicit
workload-specific local regression ceilings and retained-history replay.

The copied official-data stress configuration has 55,130 records and
1,339,047 cells. An accelerated 30-cycle x86 run captured in 3.34-5.50 seconds
per sample and reached a **1,662.8 MiB process lifetime peak working set**.
Baseline creation/resume remained about 45/31 seconds. These results expose
an unresolved memory/latency boundary, not a full-capture fix, universal
memory guarantee or multi-hour FCS Extended acceptance.

608 core checks and the plugin build passed. The full copied-vanilla runner
passed 269 general, 16 settings, 24 scheduling, 24 export, 95 recovery and 22
sampling checks. Representative isolated settings,
scheduling, export, recovery and sampling suites passed. Its general fixture
currently lacks the selectable numeric-field record expected by the suite;
the same failure reproduced with the unchanged beta 13 host. It is not
counted as a passing general run or silently fixed in this performance change.
See the wiki for detailed measurements and current regression evidence.

## Installation and compatibility

Requirements: Windows, .NET Framework 4.8, installed FCS Extended and the
inspected Steam FCS 2.14.2 executable with SHA-256:

```text
3688c4d8421d51c2d30c2ff0338874779d91eff150c6a02bf415bc1cdd9c7796
```

Back up the actual mod and relevant native notes files first. Close FCS, extract
the archive and copy its `FCS-Scribe` folder into `<Kenshi>\mods\FCS-Scribe`,
replacing older plugin files. Launch FCS Extended and enable FCS-Scribe.
Existing projects need no migration; keep their baseline and complete matching
`.scribe` folder. For large/slow stacks, use Manual initially; longer intervals
reduce capture frequency, not the duration/peak of an individual capture.

The archive contains this project's plugin, manifest, README, security policy,
documentation, GPL-3.0 license and exact-source `release.json`, not upstream
game/FCS binaries or profiling fixtures. Verify the ZIP with its `.sha256`
asset; the matching Git tag/source archives supply corresponding source.

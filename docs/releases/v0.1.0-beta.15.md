# FCS-Scribe v0.1.0-beta.15

Experimental beta with a bounded **S12 full-capture memory improvement**.
S12 remains open for representative custom-stack headroom and a sustained
real FCS Extended soak; this does not begin S13 or new feature expansion.

## Changes since v0.1.0-beta.14

- Share repeated immutable cell strings within one native capture or validated
  loaded baseline: paths, layers, sources, reference IDs, kinds and value text.
- Preserve independently mutable cells/values and ordinal/null/empty/missing
  semantics. Pools are local to each capture/load, never global interning or
  a retained adapter cache.
- Strengthen native profiling to require unchanged record/cell coverage,
  fingerprints and zero recorded changes over repeated observations.
- Add a read-only compatibility check for copied pre-change full baselines.
  Update measured memory/latency guidance without claiming a safe stack size.

No schema, fingerprint, serialized evidence, hash checks, replay chains,
flush/retention or capture-coverage changes. No forced GC, automatic pruning,
Save or plugin installation is introduced.

## Measured improvement and remaining limits

In the same copied official-data x86 stress configuration (55,130 records /
1,339,047 cells), 30 capture/review cycles reduced process lifetime peak working
set from **1,662.8 MiB to 896.7 MiB: about 46%**. Final unchanged-review managed/
private endpoints were 367.5/404.3 MiB versus 1,122.7/1,162.9 MiB.
These are local observations affected by natural GC timing, not a universal
memory cap or proof of leak-free/unbounded operation.

Native capture median was 4.44 seconds (range 4.04-4.97), compared with 4.15
seconds previously. Unchanged review median was 2.41 seconds, maximum 3.49;
actual Review includes capture plus comparison. Baseline creation/resume
remained about 45/31 seconds. This is a memory improvement, not a UI-pause fix.
The official-data stress setup is not a representative custom extension stack
or multi-hour interactive editor session.

616 core checks and the plugin build passed. The full copied-vanilla native
matrix passed 269 general, 16 settings, 24 scheduling, 24 export, 95 recovery
and 22 sampling checks. All three published synthetic history workloads
remained inside their local timing/128 MiB envelopes. A pre-change full
55,130-record baseline retained its fingerprint, serialized-state hash and
original file bytes after compaction. The previously documented representative
general-suite fixture limitation remains; no new general pass is claimed.

## Installation and compatibility

Requirements: Windows, .NET Framework 4.8, installed FCS Extended and the
inspected Steam FCS 2.14.2 executable with SHA-256:

```text
3688c4d8421d51c2d30c2ff0338874779d91eff150c6a02bf415bc1cdd9c7796
```

Back up the actual mod and relevant native notes files first. Close FCS, extract
the archive and copy its `FCS-Scribe` folder into `<Kenshi>\mods\FCS-Scribe`,
replacing older plugin files. Launch FCS Extended and enable FCS-Scribe.
Existing projects need no migration or baseline rewrite; preserve the baseline
and complete matching `.scribe` folder. Use Manual on large/slow stacks;
longer intervals reduce capture frequency, not per-capture duration/peak.

The archive includes this project's plugin, manifest, README, security policy,
documentation, GPL-3.0 license and exact-source `release.json`, not upstream
game/FCS binaries or profiling fixtures. Verify the ZIP with its `.sha256`
asset; the matching Git tag/source archives supply corresponding source.

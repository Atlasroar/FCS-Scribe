# FCS-Scribe v0.1.0-beta.17

Experimental beta completing bounded **S14 portability/linear-history guidance**.
Tracking-only moves differ from moving the active mod. No automatic relocation,
history transplantation, journal merging or identity bypass is introduced.

## Changes since v0.1.0-beta.16

- Explain native mod-path and loaded/locked-context mismatches with an explicit
  original-context or **New tracking JSON with a new filename** route.
- Explain divergent/reordered history with a coherent-branch restoration route,
  not automatic merging.
- Document closed tracking-only moves, fresh baselines after moving mods or
  changing machines, and safe handling of independently valid forked histories.
- Verify byte-preserving rejection of unioned sibling sessions, concatenated
  valid branch suffixes, reordered intact lines and mismatched sibling markers.
- Verify native tracking-set move/rename, moved-mod rejection before discrepancy
  approval, and explicit fresh-baseline creation without importing old history.

Native identity, loaded/locked guards, hashes, replay, schemas, fingerprints,
retention, default folders and draft approval are unchanged. Existing projects
need no migration. S09 full acceptance and S15/S16 remain open; S12 is accepted
only for its documented tested scope.

## Verification and limits

657 core checks passed. Copied official-data and representative-mod recovery
suites each passed 112 checks. Actual native cases preserve two compiled
observations after moving the complete closed tracking set under unchanged
mod identity. A byte-identical same-filename mod copied elsewhere cannot
Resume that project; explicit New at a fresh filename captures its new identity
without rewriting the old files or saving either mod/notes.

These are disposable same-host supported-build tests, not physical cross-machine
installation, all dependency versions, network shares or path-alias guarantees.
Equal path strings do not prove equal machine/data identity. An initial overly
long test destination hit the existing .NET path limit; shorter paths passed.
No long-path fallback or distributed lock is added. The previously documented
representative general-suite fixture limitation remains; no new general-suite
or full interactive acceptance is claimed. No live data was modified.

## Installation and compatibility

Requires Windows, .NET Framework 4.8, installed FCS Extended and the inspected
Steam FCS 2.14.2 executable with SHA-256:

```text
3688c4d8421d51c2d30c2ff0338874779d91eff150c6a02bf415bc1cdd9c7796
```

Back up the actual mod, relevant Notes/TODO files and complete private tracking
set first. Close FCS, extract the archive and copy its `FCS-Scribe` folder into
`<Kenshi>\mods\FCS-Scribe`, replacing older plugin files. Launch FCS Extended
and enable FCS-Scribe. Preserve the baseline and complete matching `.scribe`
folder; keep private tracking, backups and draft workspaces out of upload
content. Scribe does not inspect or block native Workshop uploads.

The archive contains this project's plugin, manifest, README, security policy,
documentation, GPL-3.0 license and exact-source `release.json`, not upstream
game/FCS binaries or test fixtures. Verify the ZIP with its matching `.sha256`
asset; the matching Git tag/source archives supply corresponding source.

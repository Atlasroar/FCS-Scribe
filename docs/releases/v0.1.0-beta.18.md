# FCS-Scribe v0.1.0-beta.18

Experimental beta completing bounded **S15 note-application safety**.
No rollback, automatic save, marker repair or stale/partial-coverage bypass.
S09 full acceptance and S16 remain open.

## Changes since v0.1.0-beta.17

- Report newly confirmed, previously completed/skipped and unconfirmed record
  IDs plus the active notes file. Confirmation requires exact unique-block
  readback after native append, not disk persistence.
- Preserve target, stage, original cause and detailed outcomes on partial
  failure; keep the complete original draft/packet and pause automatic work.
- Mark FCS dirty before attempting append: an unconfirmed native failure may
  already have changed memory, even with zero confirmed records.
- Name the actual shared Notes/TODO destination in approval and explain its
  separate closed-writer backup/distribution boundary. Destination changes
  during approval reject before writing.
- Keep original complete-draft retry rules, exact unique completed blocks,
  category/inherited-note preservation and explicit normal FCS Save.
- Add isolated `-NotesOnly` checks and a separate cold-reopen test process.

Packet/workspace/journal schemas, fingerprints, note-block format, identity,
default folders, retention and full-coverage guards are unchanged. Existing
projects need no migration. No live plugin installation is performed.

## Verification and limits

664 core checks and plugin build passed. Copied official-data and augmented
representative fixtures each passed 36 notes-safety checks plus 8 cold-process
reopen checks. Small fixtures receive native disposable records when needed;
the existing representative general-suite numeric-field limitation is unchanged.

A completion-observer exception is injected after one real native append,
before the next target. Checks cover confirmed/unconfirmed IDs, original
draft/report retention, no automatic save, duplicate-marker refusal, original
workspace reapproval, skipping the completed block, inherited TODO/category/
unrelated annotation preservation and an unchanged other-author sidecar.
Explicit native Save/reload and a separate native test-host process retain
one completed block per target and reject duplicate application.

Native Save can normalize dependency metadata and stale earlier evidence;
final retry fixtures deliberately Save/reload gameplay before export. Native
aggregated note formatting can normalize too. No fingerprint guard was weakened.
Unchanged current state and exact canonical blocks remain required.

No live data changed. Native mid-append I/O, every refresh/dirty-set failure,
physical power loss and complete interactive FCS Extended startup/approval are
not established by the injected between-record or cold-test-host checks.

## Installation and compatibility

Requires Windows, .NET Framework 4.8, installed FCS Extended and the inspected
Steam FCS 2.14.2 executable with SHA-256:

```text
3688c4d8421d51c2d30c2ff0338874779d91eff150c6a02bf415bc1cdd9c7796
```

Back up the actual mod, relevant shared `data\__TODO__<user>.txt` sidecars and
complete private tracking set first. Close FCS, extract the archive and replace
the `FCS-Scribe` folder in `<Kenshi>\mods\FCS-Scribe`. Launch FCS Extended and
enable FCS-Scribe. Preserve private workspaces separately; keep tracking,
backups and whole shared sidecars out of public upload content.

The archive contains this project's plugin, manifest, README, security policy,
documentation, GPL-3.0 license and exact-source `release.json`, not upstream
game/FCS binaries or test fixtures. Verify the ZIP with its matching `.sha256`
asset; the matching Git tag/source archives supply corresponding source.

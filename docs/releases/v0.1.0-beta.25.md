# FCS-Scribe v0.1.0-beta.25

Experimental beta adding **Workspace > Manage History**: guided, manually
confirmed archival and restore of redundant compiled session-log originals.
**Every recording remains in the main journal.**

## Changes since v0.1.0-beta.24

- Show baseline, journal, session-original and recovery/other storage sizes,
  plus closed eligible, active and uncompiled/dependent session counts.
- Start with nothing selected. Optional last-activity age and keep-newest
  eligible-session guides combine only when **Select matching sessions** is
  pressed; inspect/check individual eligible rows or clear the selection.
- Choose a private archive folder outside Kenshi/upload and reserved tracking
  storage. Preview payload/manifest space and same/different-drive implications.
  Same-drive archival reorganizes copies, not drive space; another drive can
  reclaim source-drive space after verified copying.
- Explicitly confirm Archive or Restore, defaulting to **No**. Opening,
  refreshing, selecting and previewing save nothing; transfers also preserve
  unsaved notes/tasks and original draft/packet associations.
- Copy, flush and hash-verify every selected original, commit a verified
  project/session/checksum manifest, then remove only the exact exclusively
  opened, checksum-verified redundant source handles. Verified recovery copies
  and the manifest remain protected during removal.
- Reconcile successful source changes under the existing writer lease without
  replacing the project/current session or advancing history.
- Restore exact missing originals after validating the same baseline/project
  and compiled evidence. Recognize unchanged already-present files without
  overwrite; reject foreign/divergent history, unsafe/duplicate names, changed
  bytes and conflicts. Archive copies remain.
- Support cancellation between verified file operations and explicit partial
  outcomes/recovery paths. A committed complete manifest permits retry/restore;
  incomplete copies without one retain originals.

No automatic pruning, archive expiration, baseline replacement, native mod/
annotation restore, OCS or direct AI-provider integration is added. Active,
pending and pending-dependent originals, main journal, marker, baseline and
recovery files are retained. Recording/export identities and existing tracking,
draft, task and AI schemas remain unchanged.

## Storage, recovery and compatibility

An archive contains `manifest.json` and selected exact `sessions/*.jsonl`
originals, not a complete tracking backup. Keep independent verified private
backups and the retained main journal. History still grows; archival does not
bound replay time or memory. Byte previews describe raw file lengths, not
physical/compressed allocation or guaranteed free-space savings.

Transfers are not an all-or-nothing multi-file transaction. Preserve the
reported archive folder and remaining originals after interruption. Managed
restore needs a validating project and exact compiled journal proof; missing
baseline/journal/pending history requires coherent closed-writer backup
recovery instead. No automatic deletion of old/incomplete archives occurs.
Junctions, symbolic links and drive-relative destinations are rejected.
Manifests have an explicit 8 MiB limit; use smaller selections if necessary.

Existing tracking roots remain compatible; older builds have no managed archive
UI. Their manual archival/restore procedure requires all writers closed.
The beta 24 task-file format-2 downgrade limits still apply.

## Verification and limits

892 core checks, a warnings-as-errors plugin build, 20 non-showing synthetic
history-management checks and the existing 34 non-showing task-view checks
passed. Cases include exact copy/restore, original packets/head/debt/order,
continued recording/compilation, cold reopen, extended-journal restore,
copy/manifest/removal/restore interruptions, late external changes,
conflicting/foreign/divergent inputs, explicit selection/confirmations,
cancellation, persistent space preview and 1000/800-pixel layout.

Updated native integration/menu source compiled without execution. No visible
forms, file-selection/confirmation dialogs, FCS executable, native model or live
mod was opened. These are bounded software/fixture results, not new physical
acceptance, real cross-drive exhaustion/device-loss, process-kill or power-cut
tests. The existing checklist and earlier saved-mod discrepancy remain separate.

## Installation

Requires Windows, .NET Framework 4.8, installed FCS Extended and the inspected
Steam FCS 2.14.2 executable with SHA-256:

```text
3688c4d8421d51c2d30c2ff0338874779d91eff150c6a02bf415bc1cdd9c7796
```

Close FCS and back up mods/native annotations, Scribe notes/tasks/settings,
complete private tracking sets and draft workspaces. Verify the ZIP against its
matching `.sha256` asset, then install its `FCS-Scribe` folder normally. Never
replace upstream binaries. `release.json` binds the package to its exact source.
Publishing/building this release does not install it.

# FCS-Scribe v0.1.0-beta.4

Experimental beta addressing **S01: incomplete draft evidence coverage**.
The user-selected policy requires complete coverage, not partial documentation.

## Changes since v0.1.0-beta.3

- Require every exported change ID exactly once across all draft entries.
  Missing records/change IDs, repeated citations and unknown evidence reject
  the entire draft before any notes are appended.
- Update new AI-packet instructions to request complete, nonduplicate coverage.
  Evidence for deleted records can still be combined on a surviving target.
- Support safe partial-application retries using the original complete draft.
  Skip only targets containing one matching completed block with the same text
  and ordered citations; append only pending targets. Normalize line endings
  for comparison without changing the existing append format.
- Reject conflicting/partial blocks, multiple same-batch markers and fully
  applied drafts. Stale editor/Workshop state still blocks application.
- Show pending/skipped counts before explicit approval and improve retry
  guidance after errors. Keep normal FCS Save under user control.
- Update the Copilot plan and wiki contracts. Each stabilization issue has its
  own PR/merge/beta cycle; S02-S16 remain open.

## Installation and compatibility

Requirements: Windows, .NET Framework 4.8, installed FCS Extended and the
inspected Steam FCS 2.14.2 executable with SHA-256:

```text
3688c4d8421d51c2d30c2ff0338874779d91eff150c6a02bf415bc1cdd9c7796
```

Close FCS, extract the archive and copy its `FCS-Scribe` folder into
`<Kenshi>\mods\FCS-Scribe`, replacing the older plugin files if upgrading.
Launch FCS Extended and enable FCS-Scribe. Back up your mod projects and FCS
notes files first. Building/downloading does not install or modify your game.

Packet/tracking schemas and appended note formatting are unchanged. Existing
drafts must now cover all exported change IDs exactly once. For a retry, keep
the complete original draft, including matching already-applied entries, and
inspect FCS Notes. Do not remove completed entries or edit identifiers to
bypass validation. Conflicts require inspection rather than silent skipping.

## Remaining boundaries

- Multi-record application is still not transactional. Safe retries are not
  rollback, mod restoration or proof of factual AI correctness.
- Current captured state must still match the export. Closing Scribe still
  loses draft/export associations; S04 remains open.
- AI export still exposes pending evidence or the latest compatible saved
  batch, not accumulated history. That is the next stabilization item, S02.
- Workshop capture coupling, settings/initialization/deadline/overwrite risks,
  large-history costs, portability and other S03-S16 items remain open.
- Tracking is not a `.mod` backup. Keep the baseline JSON and required
  `.json.scribe` storage together; do not share full private tracking data
  with AI or Workshop.
- Extraction remains partial and interval-based. Full interactive FCS Extended
  acceptance, broader mod stacks and other executable builds remain unverified.

## Validation and source

Recorded checks: **157 core**, **141 disposable vanilla FCS** and **140
representative-mod FCS** checks passed. The representative mod has no instances;
that mutation was explicitly skipped there and covered by vanilla.
Coverage includes missing/duplicate citations, surviving targets for deleted
records, stale/conflicting retries and unchanged formatting. Actual FCS checks
seed a completed note, reject incomplete drafts without mutation, and verify
that retry appends only the pending target and survives normal save/reload.

The ZIP contains the plugin, manifest, README, documentation, GPL-3.0 license
and `release.json` identifying the exact source commit. No Kenshi, FCS or
upstream FCS Extended binaries are bundled. Verify the ZIP against its
`.sha256` asset; the matching Git tag/source archives supply corresponding
source. Automated disposable-copy checks do not replace interactive acceptance.

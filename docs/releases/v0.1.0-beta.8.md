# FCS-Scribe v0.1.0-beta.8

Experimental beta addressing **S05: failed project initialization leaving an
orphaned marker that blocks retry**.

## Changes since v0.1.0-beta.7

- Write an explicit pending initialization marker before committing the full
  tracking baseline. It binds the intended baseline hash, initial project/head
  identity, fingerprint and original legacy-source hash where applicable.
- If no new baseline committed, **Start tracking > New** can retry the same
  filename after the storage problem is fixed. Retry captures the current
  editor state, not a reconstruction of the failed attempt.
- If a baseline already committed, **Resume existing JSON** validates its exact
  bytes and pending metadata, then finishes the marker without rewriting that
  baseline. New reports actionable Resume guidance instead of a generic
  orphan-marker "project already exists" block.
- Make approved legacy conversion retryable while its original packet remains;
  preserve and recheck `.legacy.bak`. Committed conversions resume normally.
- Reject foreign/unflagged storage, existing session/journal/recovery data,
  changed sources and unrelated baseline/marker backups before claiming or
  overwriting them. Recheck observed inputs at commit boundaries.
- Keep completed marker serialization and tracking/session/packet/workspace
  schemas unchanged. Retain all ordinary replay, recording, draft protection,
  approval and no-silent-save behavior.
- Update the stabilization plan, wiki and beta metadata. S06-S16 remain open.

## Installation and compatibility

Requirements: Windows, .NET Framework 4.8, installed FCS Extended and the
inspected Steam FCS 2.14.2 executable with SHA-256:

```text
3688c4d8421d51c2d30c2ff0338874779d91eff150c6a02bf415bc1cdd9c7796
```

Close FCS, extract the archive and copy its `FCS-Scribe` folder into
`<Kenshi>\mods\FCS-Scribe`, replacing older plugin files when upgrading.
Launch FCS Extended and enable FCS-Scribe. Back up your mod projects and FCS
notes files first. Building/downloading does not install or change your game.

Use beta 8 or newer for pending-initialization recovery. Existing completed
tracking projects need no migration; keep their original baseline and `.scribe`
folder together. Legacy conversion still requires explicit approval and starts
from current editor state rather than restoring an earlier mod.

## Recovery boundaries

- Fix the reported permission/write/sharing/path issue before retrying. No
  baseline JSON: New with the same filename. Baseline JSON present: Resume.
  Original legacy packet still present: Resume and approve conversion again.
- An older unflagged marker cannot prove that a failed attempt owned it.
  Restore its matching baseline or choose a separate filename; it is not
  automatically deleted or guessed safe. Backup-only storage, missing required
  legacy backups, changed sources and existing history also fail explicitly.
- Recovery does not recursively delete storage, reset recorded history or
  overwrite unrelated backups. Ordinary failed atomic writes remove only their
  own temporary file; forced termination may leave temporary files untouched.
- Consistency/hash checks under the cooperating writer lease are not signatures
  or a universal lock against arbitrary external writers/filesystem failures.
  Physical power loss, exhaustive ACL/disk-full behavior and full interactive
  FCS Extended acceptance remain unverified.
- Tracking is not a mod backup. Draft workspaces still require explicit saving;
  restored drafts need fresh validation and approval, and notes are still
  nontransactional editor-side annotations.

## Validation and source

Recorded checks: **428 core**, **266 disposable vanilla FCS** and **265
representative-mod FCS** checks passed. The representative mod has no instances;
that mutation was explicitly skipped there and covered by vanilla.
The new matrix covers both New and legacy conversion at marker/baseline/final
marker write, flush and before/after-commit boundaries; simulated access denial;
actual Windows sharing/target conflicts; repeated retry; committed Resume;
unrecognized ownership; changed sources and required backups. Recovered
projects record and replay normally, and actual Scribe Start/Resume paths are
exercised on copied FCS data.

A separate cross-version check generated compiled/uncompiled Workshop-context
history using the released beta 7 binary, then verified beta 8 replay/export
with exact original evidence/state and unchanged source-file hashes.

The ZIP contains the plugin, manifest, README, documentation, GPL-3.0 license
and `release.json` identifying the exact source commit. No Kenshi, FCS or
upstream FCS Extended binaries are bundled. Verify the ZIP against its
`.sha256` asset; the matching Git tag/source archives supply corresponding source.

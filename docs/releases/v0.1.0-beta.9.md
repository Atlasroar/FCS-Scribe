# FCS-Scribe v0.1.0-beta.9

Experimental beta addressing **S06: invalid settings preventing the Scribe
window from opening**.

## Changes since v0.1.0-beta.8

- Open known corrupt, unsupported, unreadable or unavailable-directory settings
  in clearly labelled **safe manual mode**, with a persistent recovery warning
  showing the source path and reason. Startup does not rewrite the original.
- Keep manual tracking, compilation, Workshop actions and draft work available.
  Use active-mod export defaults and independently disable automatic recording
  and compilation until a valid reload or explicit repaired Save.
- Add **Discard edits and reload** and **Save repaired settings** to Settings.
  Retain the current project, original packet and exact unfinished draft.
- Preserve exact readable original bytes in a unique, verified
  `settings.json.recovery-<UTC>_<unique-ID>.bak` before atomic repair. Ordinary
  `.bak` rotation and later repairs never replace these originals.
- Refuse replacement when the original cannot be read safely, changed or
  disappeared. Restore access and Reload before repairing unreadable settings.
  Cancel and failed reload never write settings.
- Serialize cooperating settings saves under an exclusive lease, recheck
  observed hashes and reject stale/concurrent changes instead of overwriting.
  Hash and deserialize the same read stream; require schema/interval fields,
  distinguish unsupported schemas and validate custom-directory availability.
- Retain schema 1 settings and all tracking/journal/packet/workspace contracts.
  Update the wiki and stabilization plan. S07-S16 remain open.

## Installation and compatibility

Requirements: Windows, .NET Framework 4.8, installed FCS Extended and the
inspected Steam FCS 2.14.2 executable with SHA-256:

```text
3688c4d8421d51c2d30c2ff0338874779d91eff150c6a02bf415bc1cdd9c7796
```

Close FCS, extract the archive and copy its `FCS-Scribe` folder into
`<Kenshi>\mods\FCS-Scribe`, replacing older plugin files when upgrading.
Launch FCS Extended and enable FCS-Scribe. Back up your mod projects and FCS
notes files first. Building/downloading does not install or change your game.
Existing valid settings and completed tracking projects need no migration.
Keep each tracking baseline and its `.scribe` folder together.

## Recovery boundaries

Settings live at `%LOCALAPPDATA%\FCS-Scribe\settings.json`. A valid explicit
reload/Save exits recovery and adopts its selected recording interval; failed
load/reload remains in manual/active-folder recovery mode. Unique original-byte
backups remain private local files and can reveal paths: do not upload them to
AI services or Workshop.

An unreadable original is not treated as an absent file and cannot authorize
repair. Unknown/programmer errors and fatal resource exhaustion still fail
explicitly. Hashes/leases coordinate cooperating beta 9 writers; they are not
authentication or universal protection from uncooperating external writers,
physical power loss or every filesystem failure.

Settings/session changes can still reset compilation deadlines (S07).
Large-model/history performance (S12) and full interactive FCS Extended
acceptance (S09) remain open. Tracking is not a mod backup; draft workspaces
require explicit saving, restored drafts need fresh validation/approval and
record notes remain nontransactional editor-side annotations.

## Validation and source

Recorded checks: **458 core**, **266 existing vanilla + 16 isolated settings
recovery**, and **265 existing representative-mod + 16 isolated settings
recovery** checks passed. The representative mod has no instances; that
mutation was explicitly skipped there and covered by vanilla.

The new matrix covers malformed/null/missing-required/unsupported settings,
invalid intervals/paths, missing custom directories, actual Windows read and
replacement sharing denial, unknown hashes, failed replacement with intact
originals, unique recovery backups, stale/deleted files and two simultaneous
cooperating saves. Actual Scribe windows exercise corrupt/locked startup,
manual gameplay recording during recovery, automatic-work gating,
reload/repair/cancel and project/packet/draft preservation.

Recovery checks run in a fresh 32-bit host. Earlier combined/full-debug runs
exhausted address space; the final runner isolates scenarios and uses PDB-only
symbols without claiming a production memory fix. Exhaustive ACL/disk-full,
network filesystems, physical power loss and complete real-editor interactions
are not established by these checks.

The ZIP contains the plugin, manifest, README, documentation, GPL-3.0 license
and `release.json` identifying the exact source commit. No Kenshi, FCS or
upstream FCS Extended binaries are bundled. Verify the ZIP against its
`.sha256` asset; the matching Git tag/source archives supply corresponding source.
